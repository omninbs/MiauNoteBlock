## 1. 概述与目标

本次交付三大模块加一项附带修改：

1. **音频导出**（模块 A）：把当前 NBS 歌曲离线渲染为音频文件（mp3/wav），导出时可选用「整曲整体风格」声音效果预设（KTV、演唱会等），风格也支持实时播放试听。
2. **自定义音色**（模块 C）：导入用户音频作为新的可演奏音色（单采样 + 基准音高，播放变速），含「音频修正」向导、信息设置、编辑器集成、持久化，以及随 NBS 的 zip 作品包导入导出与缺失/冲突处理。
3. **附带修改**（模块 F）：取消手机端隐藏「关于」按钮的强制 CSS（顶部放不下时自动进入「更多」菜单，用户已知悉）。

关键架构决策（已与用户确认）：

| 决策点 | 结论 |
| --- | --- |
| 「KTY」 | 笔误，实为 **KTV** |
| 声音效果的定义 | **整曲整体风格处理**，首批包含用户点名效果 + 我方参考市面软件补充，做成可扩展预设表 |
| 效果作用范围 | 导出时可选；**实时播放也能切换试听**（同一套 DSP 链复用于实时与离线） |
| 第三方依赖 | **允许但全部本地化**到 `static/vendor/`（项目可能离线运行） |
| 导出渲染 | **离线快速渲染**（OfflineAudioContext 基于时间预调度），重构播放时间轴为事件调度 |
| 自定义音色模型 | **单采样 + 基准音高**，播放按 key 变速（playbackRate） |

## 2. 术语与现有技术基线

| 术语 | 说明 |
| --- | --- |
| NBS 歌曲 | `{tempo, length, layers[], notes[], layer_channel_map}`；音符 `{id,tick,layer,instrument,key,velocity,pan,pitch}` |
| instrument | NBS 乐器号。本项目默认 0–19（Minecraft 20 种音符盒音色，OGG 采样） |
| 播放引擎 | `audio_engine.js`：Web Audio 采样回放。`playbackRate = 0.5*2^((key-33)/12)`（`getMinecraftPitch`），`playNote(instrument,key,velocity,pan)` 查 `NBS_INSTRUMENT_TO_SOUND` |
| 实时播放循环 | `main.js startPlaybackLoop`：requestAnimationFrame + tick 累加，每 tick 触发当格音符；无预调度、无 tempo change |
| 导出链路 | `exportNBS` → `_performExport` → `API.saveSong` → `NBSClient._writeNBS` → Blob 下载 |
| NBS 自定义乐器块 | NBS v6 文件尾部 `layers` 之后的 custom instruments 列表。**当前 `_parseNBS`/`_writeNBS` 均未实现该块**（写入处硬编码 `wByte(0)`），本模块将补齐 |
| 弹窗体系 | A 静态 `.popup`（`.popup-content > .settings-header/.settings-body/.popup-actions`）；B JS 动态 `showAppAlert/Confirm/Prompt` + `_appDialog*` |
| 本地依赖 | `static/vendor/` 目录（已有 spessasynth）；脚本带 `?v=` 版本号防缓存 |
| 持久化先例 | IndexedDB：`webnbs_soundfont`（SoundFont）、`bg_image`（背景大图）；localStorage 存配置 |

现有约束/约定（必须遵守）：触控与鼠标一致、编辑区坐标系、发布版本号提升、`Cache-Control: no-cache`。

## 4. 自定义音色系统（模块 C，先行实现）

### 4.1 数据模型

```
CustomInstrument {
  id: string          // uuid
  name: string        // 显示名（与默认 20 音色、其他自定义音色均不可重名）
  color: string       // 图标纯色 #rrggbb
  file: string        // 持久化键名 instrument_<id>.{mp3|wav|ogg}
  pitch: number       // 基准音高 key 0-87（音频「原样播放」对应的音高），修正后写入
  gain: number        // 相对响度 0-100（默认 100），由修正/试听校准
  originalName: string// 导入源文件名（仅展示）
  importedAt: number  // 时间戳
  channels: 1|2       // 单声道/立体声
  sampleRate: number  // 展示用
  duration: number    // 秒，展示用
  hash: string        // 音频文件内容 hash（SHA-256），用于 zip 去重/冲突检测
}
```

**instrument 编号策略（本项目语义）**：默认 20 种占用 0–19；自定义音色占用 **20 起**，按导入顺序递增分配，删除后不复用（避免旧文件引用错乱）。单字节上限 255，即最多 236 个自定义音色；编辑器乐器下拉列表 = 20 默认 + 全部自定义。

**NBS 文件内表示**（导出时，遵循 v6 规范尽力兼容）：
- 音符 `instrument` 写入其全局编号（20+i）。
- `_writeNBS` 补齐 v6 custom instruments 块：数量按 `(最大自定义编号 - 20 + 1)` 写满至该序号，每个块含 `名称 / 声音文件(storageKey) / 基准音高 / 按压音高`（本项目把 0–19 槽位留空占位以保证 Note Block Studio 序号对齐；本项目自身读取按「20=第一个自定义」解析）。
- `_parseNBS` 补齐该块读取并加载到 `state.customInstruments`。
- 纯 .nbs（不带资源）在其它播放器/Minecraft 中会静音——**导出弹窗将警告**，并建议导出 zip 作品包（见 §6）。

### 4.2 播放与编辑器集成

- `audio_engine.js` 扩展：`playNote` 遇到 instrument >= 20 时，走自定义音色通道——从缓存取用户 AudioBuffer，`playbackRate = 基准音频基准 key 到目标 key 的比率`（`0.5*2^((key - custom.pitch)/12)`），音量/pan 逻辑复用。
- 新增 `AudioEngine.setCustomInstrument(id, {buffer, pitch, gain}) / removeCustomInstrument(id)`；渲染与实时共用同一缓冲池。
- 实时播放循环与离线渲染器读取同一「乐器解析函数」`resolveInstrument(instrument) → {type:'default',id} | {type:'custom',id}`，保证实时/导出一致。
- 编辑器乐器下拉：追加自定义音色项，图标为纯色圆块（含颜色），组标题「自定义」。钢琴卷帘绘制时自定义音色音符用其颜色区分。

### 4.3 自定义音色管理弹窗（顶栏新入口 + 功能菜单入口）

- 顶部工具栏新增「自定义音色」按钮（`.toolbar-collapsible`，随更多菜单折叠机制自动收纳，不新增隐藏 CSS）。
- 弹窗内容：
  - 自定义音色列表（纯色图标 + 名称 + 基准音高/时长/声道），可试听、重命名、改色、删除。
  - 「导入音色」按钮 → 打开导入向导。
  - 「导出音色备份」按钮 → 全部音色 + 元数据打成 zip 下载。
  - 「导入音色备份」按钮 → 选择 zip 恢复（含冲突处理，同 §6.2 规则）。
- 空状态引导首次使用。

### 4.4 导入向导（三步骤，分步弹窗，逻辑清晰）

**步骤 1：选择音频文件**（mp3/wav/ogg/flac，受浏览器支持；`decodeAudioData` 失败则拒绝）。选择后立即解析，读取时长/采样率/声道数；立体声正常保留（我们支持立体声音色）。

**步骤 2：音频修正窗口**（对标 FL Studio Edison 的实用子集）：
- 布局：左侧「波形图」（Canvas 绘制，专业风格：中心线、振幅包络、可选多轨叠加，随播放进度绘制播放游标）；右侧「设置与操作」；底部「实时监视条」（全宽，播放时实时波动波形 + 文本：频率 Hz、检测音调名）。
- 音高检测：自研时域自相关 / YIN 算法（本地实现，无新依赖），对音频主体段检测得到「实际音调」，在波形上显示检测基准；长音频取样分析多个片段取主值，置信度不足时提示用户手动校准。
- 变调滑块：范围 ±24 半音。每滑完一次**自动试听**修正结果（变速预览）。
- 附加微调：音分微调（fine tune）、是否保留原速（变速必变时长；NBS 播放变速天然如此，向用户说明）。
- 「自动调整」按钮：一键按检测结果把基准音高对齐到用户设定的目标（默认让音频主音落在 C 键区/用户指定），可一键撤销。
- 播放控制：播放/暂停、循环区段、停止。
- 「确认」→ 把音频**重渲染为新文件**（OfflineAudioContext 变速重采样，直接修改采样数据而非记录偏移），产出 `finalBuffer`，并记录其基准音高 → 进入步骤 3。

**步骤 3：设置音色信息**：
- 名称输入（实时校验：非空、不与默认 20 名及已有自定义名重复，重复则红字提示并禁用确认）。
- 图标颜色选择（预设色板 + 自定义取色）。
- 展示简短数据（来源文件名、时长、采样率、声道、检测到的基准音高）。
- 「完成」→ 存入库（§4.5），编辑器乐器下拉即时出现该音色。

### 4.5 持久化

- **IndexedDB**（库名 `webnbs_custom_instruments`，两张表）：
  - `audio`：key=`instrument_<id>`，value=Blob（原始音频）；另存解码缓存。
  - `meta`：key=`<id>`，value=CustomInstrument 元数据（含 hash）。
- **localStorage**：`custom_instrument_list`（id 顺序 + 精简元数据）用于启动时快速列出。
- 启动流程：读列表 → 懒加载音频缓冲（点开播放/用到才 decode，避免大文件阻塞首屏）。
- 删除音色时清理两库并提示「引用该音色的 .nbs 中该乐器将静音」。

### 4.6 缺失音色处理（导入 .nbs 时）

检测到音符 instrument >= 20 但库中无对应自定义音色时：
- 若是**纯 .nbs**（无配套 zip）：弹窗提示「该文件使用了 N 个本项目缺失的自定义音色」，提供两个操作：
  1. 「替换为现有音色」→ 对每个缺失音色下拉选择替换成的乐器（默认/自定义均可），替换后静音区恢复可听。
  2. 「稍后导入」→ 中止本次 NBS 载入流程，引导先去导入作品包/音色备份，再重载文件。
- 若为 zip 作品包导入 → 走 §6.2 的自动装载，装载失败项按上述规则处理。

## 5. 音频导出与风格效果（模块 A）

### 5.1 离线渲染引擎（新文件 `audio_render.js`）

目标：把歌曲在**低于实时耗时**内渲染，且实时可听到同样效果。

- **调度重构**：实时播放循环从「rAF tick 累加」迁移到「基于 AudioContext 时间的预调度」（lookahead）：维护 tick→时间映射 `tickToTime(tick)`（含倍速/循环），实时播放器与离线渲染器共用同一个「事件迭代器」。
  - 实时模式：固定 lookahead（如 0.1s）逐批 `source.start`。
  - 离线模式：一次性遍历全部 tick，按时间轴逐个 `AudioBufferSourceNode.start(time)`。
- **离线上下文**：`new OfflineAudioContext(2, length*sr, sr)`；构建与实时一致的图：干声总线 + 效果链（§5.2）→ master 压缩 → destination。
- **音符渲染**：每个音符 = 一次采样触发（默认乐器查 OGG 缓冲、自定义查用户缓冲），`playbackRate` 按 key 映射；velocity/pan/轨道音量/轨道静音逻辑复刻实时调度器；pitch(NBS v4 微调) 并入 playbackRate。
- **速度变化**：本项目歌曲 tempo 目前为整曲固定值 + 速度变化器以「layer0 key39=TPS」特例存在（MIDI 导入生成）。渲染器对这类速度变化器音符做分段 tempo 处理（生成分段时间轴）。若评估复杂度高，第一版先按整曲固定 tempo + 如实保留速度器音符为节奏标记但仅用其所在 tick 处 tempo 分段。
- 渲染完成 → `AudioBuffer` → 编码器（§5.3）→ Blob 下载。
- 取消渲染：渲染中可点取消（大文件耗时提示 + 进度）。

### 5.2 整体风格效果预设（可扩展表）

每个预设 = 一串 DSP 参数（类型化），渲染器/实时链按参数装配节点。实时播放切换风格 = 切换参数并重建效果子图；默认「原声（无效果）」直连。

效果链通用形态：`EQ(可多段) → 可选饱和/驱动 → 混响(可切换卷积IR或算法) → 动态压缩 → 输出`；参数全表驱动，便于后续口头加新风格。

首批预设（名称 + 听感目标，参考市面音频软件场景预设）：

| 预设 | 听感设计 |
| --- | --- |
| 原声 (Dry) | 无处理，直连（默认） |
| KTV（卡拉OK） | 中频增强（人声段 1k–4k 提升）、轻房间混响、轻压缩、整体明亮靠前，伴奏欢唱感 |
| 演唱会 (Live) | 大厅/现场感混响（预延迟 + 较长衰减）、压缩使整体靠前、中低频略饱满，现场 PA 感 |
| 大厅 (Hall) | 古典大空间混响、柔和、高频略收，适合管弦/柔和曲 |
| 俱乐部 (Club) | 低频增强、偏干 + 短混响、节奏清晰，舞曲感 |
| 摇滚 (Rock) | 中频提升 + 动态压缩（结实）、轻微临场，乐队感 |
| 复古/磁带 (Retro) | 温和高频衰减（暖化）、轻度饱和/压缩，磁带/老唱片感 |
| 纯净 (Clear) | 平直 EQ + 轻压缩提升清晰度，接近母带监听 |

说明：
- 卷积混响 IR 采用本地算法生成（如噪声衰减 IR，多段参数化：房间大小/预延迟/衰减），**不新增 IR 资源文件**，保证离线可用。
- 「演唱会」「大厅」本质是同一混响器不同参数 + 压缩差异；「KTV」是 EQ+短混响组合。所有预设都做成参数表，非特殊代码路径。

### 5.3 编码与 UI

- **编码器（本地化 vendor）**：
  - mp3：`lamejs`（本地 `static/vendor/lame.min.js`），支持 CBR 比特率选择（128/192/320）。
  - wav：自研 PCM 编码（无需库，16-bit/浮点）。
- **导出弹窗（扩展 `showExportDialog`）**：新增区段：
  - 音频格式：mp3 / wav（单选分段控件；mp3 附带质量单选）。
  - 整体风格：下拉/宫格单选（含「原声」）。
  - 「导出音频」按钮 → 离线渲染进度 → 下载。
  - 若歌曲含自定义音色且仅导出 .nbs：按用户既有需求弹警告 + 提示导出作品包。
- 风格实时试听入口：播放控制条新增「风格」小菜单，切换即生效；停止后自动回到「原声」或保持选择（保留上次选择）。

## 6. 作品包 zip 导出 / 导入（模块 E）

### 6.1 导出作品包（含自定义音色时推荐）

- 触发：导出弹窗新增「导出作品包(zip)」按钮（检测到歌曲用到自定义音色时高亮提示）。
- 组成：
  - `song.nbs`（NBS v6，含 custom instruments 块）
  - 歌曲用到的每个自定义音色音频文件，**文件名 = 音色名称 + 扩展名**（重名由校验保证不存在）
  - `metadata.json`（schema 见下）
- `metadata.json` schema：

```json
{
  "type": "noteblock-web-song-pack",
  "formatVersion": 1,
  "song": "song.nbs",
  "instruments": [
    { "name": "...", "file": "钢琴.mp3", "hash": "sha256:...", "pitch": 33, "color": "#ff8844" }
  ]
}
```

- zip 使用本地 `jszip`（vendor）。文件内层目录扁平化。

### 6.2 导入作品包

1. 用户选择 zip → `jszip` 解析 → 校验 `metadata.json` 与 `type`。
2. 逐音色与本地库比对（按 `name`）：
   - 同名且 hash 相同 → 视为已存在，跳过（不重复导入）。
   - 同名但 hash 不同 → 弹窗让用户选择：**重命名导入** 或 **替换现有音色**（替换会覆盖本地同名音色；被替换前若被旧 .nbs 引用，旧引用将指向新音频——按 NBS 语义可接受）。
   - 新名称 → 直接导入。
3. 所有音色装载完成后导入 `song.nbs`（§4.6 仍生效，处理个别残留缺失）。
4. 载入完成刷新编辑器。

### 6.3 音色备份 zip（管理窗内）

- 结构：`metadata.json {type:"noteblock-web-instrument-backup", formatVersion:1, instruments:[{name,file,hash,pitch,color}]}` + 音频文件（文件名=名称）。
- 导入备份冲突规则与 6.2 完全一致（同名同 hash 跳过 / 同名异 hash 询问重命名或替换）。
- 用于浏览器数据丢失后的恢复。

### 6.4 命名与清理
